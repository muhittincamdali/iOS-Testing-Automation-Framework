iOS ve macOS uygulamalarının arayüz ve birim testleri için bir Swift paketi. XCUITest'e robotlar ekler
(her ekran için bir sınıf; metotları bekler, adımı kaydeder ve hataları sizin satırınızda bildirir),
erişilebilirlik tanımlayıcısı değişse de çalışmaya devam eden öğe aramaları, erişilebilirlik denetimi,
fark görüntüsü üreten ekran görüntüsü karşılaştırması ve CI için JUnit ile Markdown raporları sunar.
Swift Testing ya da XCTest fark etmeksizin her testte SwiftUI snapshot'ları, yoklamalı beklemeler,
yeniden denemeler, spy'lar ve tohumlu test verisi ekler. Arayüz testleri küçük arayüz değişikliklerinde
kırılan veya CI günlüğünde okunması zor olan ekipler için tasarlandı. Paketin bağımlılığı yoktur ve
yalnızca test hedeflerinize eklenir.

## Öne çıkanlar

- **Okunabilir arayüz testleri** — robotlar, `app.buttons["signIn.submit"].tap()` gibi dizileri
  `app.on(SignInRobot.self).signIn(email:password:)` çağrısına dönüştürür. Her adım, öğesine
  dokunulabilir olana kadar bekler ve Xcode'un test raporunda adlandırılmış bir adım olarak görünür.
- **Kendini onaran bulucular** — bir tanımlayıcı yeniden adlandırıldığında arama, öğeyi etiketi,
  yer tutucusu veya benzer bir tanımlayıcısı üzerinden bulur, yapılması gereken düzeltmeyi kaydeder
  ve iki öğe eşit derecede uyuyorsa tahmin yürütmeyi reddeder.
- **Gözle görülen görsel gerilemeler** — ekran görüntüleri ve SwiftUI görünümleri; bir tolerans,
  yok sayılan bölgeler (saat, tarih) ve değişen her pikselin mavi olduğu bir fark görüntüsüyle,
  temel PNG'ye karşı karşılaştırılır.
- **Her çalıştırmada erişilebilirlik** — tek bir çağrı, ekranda etiketsiz denetimleri, 44 × 44
  noktanın altındaki dokunma hedeflerini, öğe türünü tekrarlayan etiketleri ve yinelenen
  tanımlayıcıları denetler; isterseniz Apple'ın `performAccessibilityAudit()` çağrısını da ekleyebilir.
- **CI'a hazır çıktı** — her test paketi için `junit.xml` ve Markdown iş özeti; yazılan parolalar ve
  belirteçler maskelenir. Ayrıca birkaç çalıştırma üzerinden kararsız test analizi yapılır.
- **Test edilmiş kurallar** — onarıcı, denetim, görüntü karşılaştırması, raporlar ve maskeleme düz
  Swift'tir; macOS'ta ve bir iPhone simülatöründe 112 Swift Testing testiyle kapsanır.
  [Örnek uygulamadaki](Examples/AutomationShowcase) 9 arayüz testi, XCUITest katmanını CI'da baştan
  sona çalıştırır.

## Hızlı başlangıç

**1. Paketi ekleyin**

Xcode'da **File › Add Package Dependencies…** menüsünü seçin ve depo adresini girin:

```text
https://github.com/muhittincamdali/iOS-Testing-Automation-Framework.git
```

Adresi pencerenin sağ üstündeki arama alanına yapıştırın. **Dependency Rule** ayarını `2.0.0`
sürümünden başlayan **Up to Next Major Version** olarak bırakın, ardından **Add Package**'a tıklayın.
Sonraki pencerede **iOSTestingAutomationFramework** yanında **UI test hedefinizi** seçin (uygulama
hedefini değil: paket XCTest'e bağlanır) ve yeniden **Add Package**'a tıklayın.

Henüz bir UI test hedefiniz yok mu? **File › New › Target… › UI Testing Bundle** seçin.

**2. Modülü içe aktarın**

```swift
import iOSTestingAutomationFramework
```

Bu satırı UI test dosyanızın en üstüne, `import XCTest` satırının altına koyun.

**3. Kullanın**

Yeni bir Xcode uygulamasında (**File › New › Project… › App**, **Include Tests** işaretli),
`ContentView.swift` dosyasının tüm içeriğini şununla değiştirin:

```swift
import SwiftUI

struct ContentView: View {
    @State private var count = 0

    var body: some View {
        VStack(spacing: 16) {
            Text("Tapped \(count) times")
                .accessibilityIdentifier("counter.label")
            Button("Tap me") { count += 1 }
                .buttonStyle(.borderedProminent)
                .accessibilityIdentifier("counter.button")
        }
    }
}
```

Ardından UI test dosyasının (adı `UITests.swift` ile biten dosya) içeriğini şununla değiştirin:

```swift
import XCTest
import iOSTestingAutomationFramework

final class CounterRobot: Robot {
    var label: XCUIElement { app.staticTexts["counter.label"] }
    var button: XCUIElement { app.buttons["counter.button"] }
}

final class CounterUITests: XCTestCase {
    @MainActor
    func testTappingCounts() {
        let app = XCUIApplication()
        app.launch()

        let counter = app.on(CounterRobot.self)
        counter
            .tap(counter.button)
            .tap(counter.button)
            .assertLabel(of: counter.label, equals: "Tapped 2 times")
    }
}
```

**⌘U** tuşlarına basın. Test uygulamayı simülatörde açar, düğmeye iki kez dokunur ve geçer. Test
raporunda her dokunuş ve etiket denetimi ayrı bir adım olarak görünür.

## Kurulum

### Swift Package Manager

Xcode'da **File › Add Package Dependencies…** menüsünü seçin ve depo adresini girin:

```text
https://github.com/muhittincamdali/iOS-Testing-Automation-Framework.git
```

Bir `Package.swift` dosyasında bağımlılığı ekleyin ve ürünü test hedeflerinizin altına yazın:

```swift
dependencies: [
    .package(url: "https://github.com/muhittincamdali/iOS-Testing-Automation-Framework.git", from: "2.0.0")
],
targets: [
    .testTarget(name: "YourAppTests", dependencies: [
        .product(name: "iOSTestingAutomationFramework", package: "iOS-Testing-Automation-Framework")
    ])
]
```

## Kullanım

Arayüz testi örnekleri [örnek uygulamanın arayüz testlerinden](Examples/AutomationShowcase/AutomationShowcaseUITests),
birim testi örnekleri ise
[`ReadmeExamples.swift`](Tests/iOSTestingAutomationFrameworkTests/ReadmeExamples.swift) dosyasından
alınmıştır; CI ikisini de çalıştırır.

### Her ekran için bir robot yazın

```swift
final class SignInRobot: Robot {
    var email: XCUIElement { app.textFields["signIn.email"] }
    var password: XCUIElement { app.secureTextFields["signIn.password"] }
    var submit: XCUIElement { app.element(Locator("signIn.submit", label: "Sign In", kind: .button)) }
    var error: XCUIElement { app.staticTexts["signIn.error"] }

    @discardableResult
    func signIn(email address: String, password secret: String) -> CatalogRobot {
        type(address, into: email)
        typeSecret(secret, into: password)
        tap(submit)
        return on(CatalogRobot.self)
    }
}
```

Testler böylece bir test senaryosunun adımları gibi okunur:

```swift
app.on(SignInRobot.self)
    .signIn(email: "ada@example.com", password: "correct-horse-battery")
    .assertCart(contains: 0)
    .open("grinder")
    .addToCart(times: 2)
    .goBack()
    .assertCart(contains: 2)
```

`typeSecret(_:into:)` parolayı kaydeder; böylece parola adım adlarında, hata iletilerinde ve
raporlarda `••••` olarak maskelenir.

### Bir tanımlayıcı değiştiğinde testleri çalışır tutun

Bir `Locator`, tanımlayıcının yanında kullanıcının gördüğü etiketi veya yer tutucuyu da taşır.
Aşağıdaki testte, yeniden tasarımdan önceki tanımlayıcı hâlâ kullanılıyor:

```swift
// "loginButton" was the identifier before the redesign; the app now uses "signIn.submit".
let button = app.element(Locator("loginButton", label: "Sign In", kind: .button), timeout: 1)
XCTAssertTrue(button.exists)
XCTAssertEqual(button.identifier, "signIn.submit")
```

Onarılan arama, düzeltmeyle birlikte `HealingLog` kaydında ve Markdown raporunda görünür:
`Update the locator "loginButton" to "signIn.submit"`.

### Erişilebilirliği denetleyin

```swift
app.on(SignInRobot.self).assertAccessible()
```

Her sorun bir test hatasına dönüşür. Sorunları kendiniz incelemek için:

```swift
let issues = try app.accessibilityIssues()
let favoriteIssues = issues.filter { $0.element.identifier == "audit.favorite" }.map(\.rule)
XCTAssertEqual(Set(favoriteIssues), [.missingLabel, .smallTouchTarget])
```

### Ekran görüntülerini karşılaştırın

`assertScreenshot(named:of:ignoring:)`, uygulamayı (ya da tek bir öğeyi) test dosyasının yanındaki
`__Snapshots__/` klasöründe saklanan temel PNG ile karşılaştırır; kendiliğinden değişen öğeleri
dışarıda bırakır:

```swift
catalog.assertScreenshot(named: "catalog", ignoring: [catalog.lastUpdated], comparator: comparator, store: store)
```

İlk çalıştırma temel görüntüyü kaydeder ve başarısız olur; böylece eksik bir temel görüntü sessizce
geçmez. Uyuşmazlıkta temel görüntü, gerçek ekran görüntüsü ve fark görüntüsü test raporuna eklenir.

### Birim testinde bir SwiftUI görünümünün snapshot'ını alın

```swift
@Test @MainActor func signalBarsLookRight() throws {
    try assertSnapshot(of: SignalBars(level: 3), named: "signal-bars-3", size: CGSize(width: 44, height: 32))
}
```

`assertSnapshot`, sorun kaydetmek yerine hata fırlatır; bu yüzden Swift Testing'de ve XCTest'te aynı
şekilde çalışır.

### Eşzamansız durumu bekleyin ve sahte bir nesneyi denetleyin

```swift
struct FakeUserService: UserService {
    let fetchUser = ThrowingSpy<Int, String>(returning: "Ada")

    func user(id: Int) async throws -> String {
        try fetchUser(id)
    }
}

@Test @MainActor func profileLoadsTheUser() async throws {
    let service = FakeUserService()
    let model = ProfileModel(service: service)

    model.load(id: 42)

    try await Wait.until("the name to load") { model.name == "Ada" }
    #expect(service.fetchUser.inputs == [42])
}
```

### Sonuçları CI'da raporlayın

Toplayıcıyı UI test paketinizde bir kez kurun:

```swift
override class func setUp() {
    super.setUp()
    // Writes junit.xml and summary.md when TESTING_AUTOMATION_REPORT_DIR is set.
    TestResultCollector.install(reportName: "AutomationShowcase UI tests")
}
```

ve testleri çalıştırırken rapor klasörünü belirtin:

```sh
TEST_RUNNER_TESTING_AUTOMATION_REPORT_DIR="$PWD/reports" xcodebuild test \
  -scheme AutomationShowcase -destination 'platform=iOS Simulator,name=iPhone 17 Pro'
cat reports/summary.md >> "$GITHUB_STEP_SUMMARY"   # on GitHub Actions
```

Kendi sonuçlarınızdan bir rapor oluşturmak için:

```swift
let report = TestReport(name: "Nightly", results: results)
let xml = report.junitXML()
```

## Mimari

- `Sources/iOSTestingAutomationFramework/` altında her alan için bir klasör vardır: `Core`, `Reporting`,
  `Waiting`, `Resilience`, `Locators`, `Accessibility`, `Visual`, `Doubles`, `Fixtures`,
  `Performance` ve `XCUI`.
- `XCUI` dışındaki her şey düz Swift'tir. Kurallar (onarım, denetim, görüntü karşılaştırması,
  raporlar, maskeleme) `ElementDescriptor` ve `Bitmap` gibi değerler üzerinde çalışır; böylece birim
  testleri çalışan bir uygulama olmadan onları kapsar. `XCUI` ince bir katmandır: ekranın tek bir
  anlık görüntüsünü tanımlayıcılara çevirir ve hataları XCTest üzerinden bildirir.
- Paket Swift Testing'i içe aktarmaz: Xcode, UI test paketlerini Swift Testing olmadan derler; bu
  yüzden ona bağımlı olmak her UI test hedefini bozardı. Birim testleri için yazılmış doğrulamalar
  hata fırlatır; iki çatı da bunu başarısızlık olarak raporlar.
- Test dışından gelen girdi sınırlandırılmıştır: görüntü boyutları çözülmeden önce denetlenir,
  snapshot adları güvenli dosya adlarına dönüştürülür, NaN ve sonsuz sayılar dönüştürülmek yerine
  sınırlanır ve girdiyle büyüyen her listenin bir sınırı vardır.
- CI, macOS'ta `swift test`, bir iPhone simülatöründe `xcodebuild test` çalıştırır; iOS ve macOS için
  derler, örnek uygulamanın arayüz testlerini çalıştırır ve DocC dokümantasyonunu yayımlar.

Testleri yerelde çalıştırın:

```sh
swift test                                    # macOS
xcodebuild test -scheme iOSTestingAutomationFramework \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro'
cd Examples/AutomationShowcase                # the UI tests
xcodebuild test -scheme AutomationShowcase \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro'
```

- Farklı makinelerde alınan ekran görüntüleri için algısal bir renk toleransı.
